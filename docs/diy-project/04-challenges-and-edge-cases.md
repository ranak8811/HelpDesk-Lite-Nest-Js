# 04. Challenges and Edge Cases (ইঞ্জিনিয়ারিং ট্র্যাপ ও সমাধান)

নতুন প্রজেক্ট নিজে নিজে তৈরি করার সময় অনেক সময় এমন কিছু "অদ্ভুত" বাগ (Bugs) দেখা দেয় যা ঘণ্টার পর ঘণ্টা মাথা নষ্ট করতে পারে। এই গাইডে আমরা এমন ৬টি গুরুত্বপূর্ণ ফাঁদ ও চ্যালেঞ্জ নিয়ে আলোচনা করব, যা ভালো ও অভিজ্ঞ ইঞ্জিনিয়াররা সবসময় মাথায় রাখেন।

---

## ১. Trap 1: `useDefineForClassFields` এবং DTO ভ্যালিডেশন ফেইল হওয়া

* **লক্ষণ:** তুমি DTO-তে `@IsNotEmpty()`, `@IsString()` ইত্যাদি ডেকোরেটরস বসিয়েছ, অথচ Postman থেকে ভুল ডেটা পাঠালেও কোনো ভ্যালিডেশন এরর আসছে না বা প্রোপার্টিগুলো গায়েব হয়ে যাচ্ছে!
* **কারণ:** TypeScript 4.3+ এবং আধুনিক ES সংস্করণে ক্লাস ফিল্ড হ্যান্ডলিংয়ের নিয়মে পরিবর্তন এসেছে। এর ফলে `class-validator` ক্লাসের মেটাডাটা পড়তে পারে না।
* **সমাধান:** `tsconfig.json` ফাইলের `compilerOptions`-এ নিশ্চিত করো:
  ```json
  "useDefineForClassFields": false
  ```
  এটি সেট করার পর সার্ভার একবার রিস্টার্ট (`npm run start:dev`) দেবে।

---

## ২. Trap 2: Strict Equality (`===`) এবং টাইপ কনভার্সন

* **লক্ষণ:** তুমি `GET /api/events/1` কল করেছ, ইভেন্ট অ্যারিতে ১ নম্বর ইভেন্ট থাকা সত্ত্বেও `NotFoundException` (404) খাচ্ছ!
* **কারণ:** HTTP রিকোয়েস্টে URL প্যারামিটার (যেমন `:id`) সর্বদা **`string`** আকারে আসে।
  তুমি যদি কন্ট্রোলারে লেখো:
  ```typescript
  // ভুল পদ্ধতি:
  @Get(':id')
  findOne(@Param('id') id: number) // এখানে টাইপস্ক্রিপ্ট টাইপ 'number' লিখলেও রানটাইমে এটি আসলে string '1'!
  ```
  আর সার্ভিসে যদি করো: `events.find(e => e.id === id)` অর্থাৎ `1 === '1'`, যা JavaScript-এ `false` রিটার্ন করে!
* **সমাধান:** কন্ট্রোলারে অবশ্যই NestJS-এর বিল্ট-ইন **`ParseIntPipe`** ব্যবহার করবে:
  ```typescript
  @Get(':id')
  findOne(@Param('id', ParseIntPipe) id: number)
  ```
  `ParseIntPipe` রানটাইমে স্ট্রিংটিকে আসল নাম্বারে কনভার্ট করে সার্ভিসে পাঠাবে।

## ৩. Trap 3: সঠিক HTTP Status Code নির্ধারণ (400 vs 404 vs 403)

এপিআই ডিজাইনের ক্ষেত্রে ভুল স্ট্যাটাস কোড পাঠানো খুব বাজে ইঞ্জিনিয়ারিং প্র্যাকটিস। নিচের টেবিলটি মুখস্থ করে নাও:

| দৃশ্যপট (Scenario) | ভুল কোড | সঠিক কোড | কারণ |
| :--- | :---: | :---: | :--- |
| এমন আইডি চাওয়া হলো যা অ্যারিতে নেই | 400 | **404 Not Found** | রিসোর্সটি সিস্টেমে বিদ্যমান নেই |
| আইডির জায়গায় স্ট্রিং পাঠানো হলো (`/events/abc`) | 404 | **400 Bad Request** | ক্লায়েন্টের ইনপুট ফরম্যাট ভুল |
| এমন ইভেন্ট বুক করার চেষ্টা যার সব সিট পূর্ণ | 500 / 404 | **400 Bad Request** | ডেটা আছে, কিন্তু বিজনেসের শর্ত লঙ্ঘন হয়েছে |
| ক্যান্সেল অ্যান্ডপয়েন্টে অ্যাডমিন হেডার নেই | 401 / 400 | **403 Forbidden** | ইউজার অনুমোদিত নয় |
| কুয়েরি প্যারামিটারে ভুল ক্যাটাগরি পাঠানো হলো | 200 (খালি) | **400 Bad Request** | DTO ভ্যালিডেশন আটকে দিয়েছে |

## ৪. Trap 4: Guard ও Execution Order এর রহস্য

* **ঘটনা:** মনে করো তুমি `PATCH /api/events/9999/cancel` অ্যান্ডপয়েন্টে রিকোয়েস্ট পাঠালে যেখানে কোনো অ্যাডমিন হেডার (`x-admin-key`) দিলে না।
* **প্রশ্ন:** এখানে রেসপন্স কী আসা উচিত? `404 Not Found` (কারণ ৯৯৯৯ নম্বরের কোনো ইভেন্ট নেই) নাকি `403 Forbidden`?
* **উত্তর:** রেসপন্স আসবে **`403 Forbidden`**!
* **কেন?**
  NestJS-এর রিকোয়েস্ট লাইফসাইকেলে **Guard এক্সিকিউট হয় Pipe এবং Controller-এর আগে**।
  যেহেতু গার্ড আগেই চেক করে দেখেছে যে ইউজারের সিক্রেট কি নেই, তাই রিকোয়েস্ট সার্ভিস পর্যন্ত পৌঁছাতেই পারবে না! সিকিউরিটির নিয়মই হলো: **"অনুমতি না থাকলে সিস্টেমের ভেতর কী আছে বা নেই তা জানানো নিষেধ।"**

## ৫. Trap 5: `ValidationPipe`-এ `transform: true` ভুলে যাওয়া

গ্লোবাল ভ্যালিডেশন পাইপে যদি `transform: true` না লেখো:
```typescript
// দুর্বল কনফিগারেশন:
new ValidationPipe({ whitelist: true })
```
তবে DTO অবজেক্টটি সাধারণ প্লেইন জাভাস্ক্রিপ্ট অবজেক্ট (`Object`) হিসেবে থাকবে, ক্লাসের ইনস্ট্যান্স হবে না। ফলে DTO-তে যদি কোনো মেথড বা টাইপ কাস্টিং ডেকোরেটর (`@Type(() => Number)`) ব্যবহার করো, তা কাজ করবে না।

**সেরা প্র্যাকটিস:**
```typescript
app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,
    forbidNonWhitelisted: true,
    transform: true, // এটি নিশ্চিত করবে ইনকামিং ডেটা আসল DTO ক্লাসের ইনস্ট্যান্সে রূপান্তরিত হয়েছে
  }),
);
```

## ৬. Trap 6: ইন-মেমোরি স্টেট মিউটেশন বনাম পিউর অবজেক্ট রিটার্ন

ইন-মেমোরি অ্যারিতে কাজ করার সময় সরাসরি রেফারেন্স ধরে পরিবর্তন করলে মাঝে মাঝে ব্যাকগ্রাউন্ড সাইড-ইফেক্ট হতে পারে:
```typescript
// ঝুঁকিপূর্ণ মিউটেশন:
event.title = updateDto.title;
return event;
```
ইঞ্জিনিয়ারিংয়ের ক্ষেত্রে ইমিউটেবল প্যাটার্ন বা অবজেক্ট স্প্রেডিং অনুসরণ করা অধিক নিরাপদ:
```typescript
// ক্লিন ও প্রফেশনাল প্যাটার্ন:
const eventIndex = this.events.findIndex(e => e.id === id);
if (eventIndex === -1) {
  throw new NotFoundException(`Event with ID ${id} not found`);
}

const updatedEvent = {
  ...this.events[eventIndex],
  ...updateDto,
};

this.events[eventIndex] = updatedEvent;
return updatedEvent;
```
